## 1. 通用约定

### 1.1 统一响应结构

成功与业务错误均返回 HTTP 200，结构为：

```json
{ "code": 0, "msg": "ok", "data": { }, "traceId": "a1b2c3d4" }
```

- `code = 0` 成功；非 0 为业务/系统错误。
- `traceId`：本次请求随机 12 位十六进制，用于排障。**同一个值会出现在响应头 `X-Trace-Id` 与服务端 `api_run.log` 的 `ACCESS`/`UNHANDLED` 行里**，客户端可凭它对账。
- ⚠️ **例外 1**：参数校验失败时 FastAPI 返回 **HTTP 422**，体为 `{"detail":[{"type":"...","loc":[...],"msg":"..."}]}`，不含 `code/msg`。前端需同时处理两种形态。
- ⚠️ **例外 2**：未捕获异常返回 **HTTP 500**，体为固定文案 `{"code":50000,"msg":"internal error","data":null,"traceId":"..."}`
  ——**不再回显异常原文**（原实现会把 pymysql 报错、表名、SQL 片段、文件路径回给客户端）。

### 1.2 错误码（实际实现）

| code | HTTP | 含义 | 触发场景 |
|------|------|------|----------|
| 0 | 200 | 成功 | — |
| 40001 | 200 | 参数不合法 | 未知 `task`；非法日期（`?start=abc`、`20261301`）；`start > end` |
| 40102 | 200 | 管理接口不可用 / 密钥错误 | `ADMIN_KEY` 未配置或仍为默认值；`X-Admin-Key` 不匹配 |
| 40301 | 200 | 管理接口来源 IP 不在白名单 | 配置了 `ADMIN_IP_ALLOWLIST` 且当前 IP 不在其中 |
| 40401 | 200 | 资源不存在 | 行业/股票代码不存在（含 `/members`、`/stocks-flow`） |
| 42901 | 200 | 采集任务已在运行 | `POST /admin/fetch` 并发触发（进程内闸门或审计表 running 行） |
| 42902 | 200 | 管理接口触发频率超限 | 超过 `ADMIN_RATE_LIMIT_PER_MIN`（默认 30 次/分钟/IP） |
| 50000 | 500 | 服务器内部错误 | 未捕获异常（响应体固定 `internal error`，细节只在服务端日志） |
| —（422） | 422 | 参数校验失败 | FastAPI 原生，**非统一结构** |

> 未实现：`40101`（读接口鉴权）、`50301`（数据未就绪）；其余参数校验错误由 FastAPI 返回原生 422。

### 1.3 单位与格式

| 项 | 约定 |
|----|------|
| 金额 | **亿元**，数值型，保留 4 位小数（如 `1.2345`） |
| 成交量 | **手**（1 手 = 100 股，仅 `t_moneyflow` 原始表内，接口未暴露） |
| 日期 | 响应统一 `YYYY-MM-DD`；请求区间参数接受 `YYYY-MM-DD` 或 `YYYYMMDD` |
| 行业代码 | 申万代码，去 `.SI` 后缀，如 `801081`（二级）、`850131`（三级） |
| 股票代码 | `ts_code`，如 `600519.SH` |

### 1.4 鉴权（实际）

- **读接口：无鉴权**（`X-Api-Key` 未实现）。
- **管理接口**（`/admin/fetch`、`/admin/log`）：请求头 `X-Admin-Key: <key>`，与后端环境变量 `ADMIN_KEY` 比对。
- **fail closed**：若 `ADMIN_KEY` 未配置，或仍等于默认值 `change-me-admin-key`，管理接口**一律返回 `40102`**
  （后端不再回退到默认密钥；启动时会在控制台打印 `[WARN]`）。

### 1.5 分页（各接口上限不同）

统一参数 `page`（默认 1）、`page_size`，响应：

```json
{ "code": 0, "msg": "ok", "data": { "list": [], "total": 0, "page": 1, "page_size": 20 } }
```

| 接口 | page_size 默认 | 上限 |
|------|---------------|------|
| `/industries` | 20 | **1000** |
| `/industries/{code}/members` | 50 | 100 |
| `/stocks/search` | 10 | 100 |
| `/industries/{code}/stocks-flow` | 用 `limit`，默认 100 | 500 |

## 3. 接口详情

### 3.1 健康检查

`GET /api/v1/health`

**任何情况都返回 HTTP 200**（DB 挂掉也返回 200，用 `db` 字段表达状态，便于探针区分「服务活着但数据库不可用」）：

```json
{ "code": 0, "msg": "ok",
  "data": { "status": "up", "db": "up", "latestTradeDate": "2026-09-30" } }
```

```json
{ "code": 0, "msg": "ok",
  "data": { "status": "down", "db": "down", "latestTradeDate": null } }
```

> `status` 与 `db` 同义（DB 通即 `up`）。连接获取与两条查询在同一 `try` 内，
> 因此 MySQL 不可达时**必然**能返回 `down` 而不是 500。

### 3.2 元信息

`GET /api/v1/meta`

```json
{ "code": 0, "msg": "ok",
  "data": {
    "dataStart": "2025-09-29",
    "dataEnd": "2026-09-30",
    "industryCount": { "l1": 31, "l2": 134, "l3": 346 },
    "stockCount": 5571,
    "generatedAt": "2026-10-06 16:46:08",
    "source": "tushare-compatible-proxy"
  } }
```

> `generatedAt` 为本次响应生成时间（Asia/Shanghai，`YYYY-MM-DD HH:MM:SS`）——v1.3 起不再恒为 `null`。
> `dataStart/dataEnd` 取自 `t_moneyflow` 的日期范围。

### 3.3 行业列表

`GET /api/v1/industries?level=2&l1=电子&q=半&page=1&page_size=20`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| level | int | 否 | 1/2/3，默认 2 |
| l1 | string | 否 | 一级行业名精确匹配 |
| q | string | 否 | 行业名/代码模糊搜索 |
| page / page_size | int | 否 | 分页（page_size ≤ 1000） |

```json
{ "code": 0, "msg": "ok",
  "data": {
    "list": [
      {
        "swCode": "801081", "name": "半导体", "level": 2,
        "l1Name": "电子", "memberCount": 180, "directMemberCount": 7,
        "topStocks": ["德明利", "紫光国微", "大港股份", "康强电子"],
        "todayNet": -132.3201, "todayMain": -97.6903,
        "main5d": -373.117, "main10d": -152.2493,
        "net5d": -356.2042, "net10d": -198.6068,
        "turnover": 1774.5337
      }
    ],
    "total": 134, "page": 1, "page_size": 20
  } }
```

> `todayNet` = 最新交易日官方净流入；`todayMain` = 最新交易日主力（大单+超大单）净流入；`main5d/main10d/net5d/net10d` = 最近 5/10 个**交易日**累计（窗口取全市场最近 10 个交易日，SQL 内聚合）；`topStocks` 按代码序取前 4 只当前成分股。
> 上述累计字段与 `todayNet` 一样恒为数值（无数据时为 `0.0`），**不会为 `null`**。
>
> **`directMemberCount`（直属成分股数）**：挂在行业自身、且未被其任一下级子行业覆盖的当前成分股数量。三级行业无子节点，故 `directMemberCount == memberCount`。
> 二级行业该值 > 0，说明存在**没有三级行业归属**的股票（数源 `index_member` 对部分股票不返回三级，见 §3.6 `direct` 参数）。全库当前共 **253 只**，分布在 46 个二级行业（光伏设备 17、化学纤维 13、多元金融/小金属/特钢Ⅱ 各 12 …）。

### 3.4 行业树

`GET /api/v1/industries/tree`（无参数）

```json
{ "code": 0, "msg": "ok",
  "data": [
    {
      "swCode": "801080", "name": "电子", "level": 1, "parentCode": null,
      "l1Name": "电子", "memberCount": 0, "directMemberCount": 0,
      "children": [
        {
          "swCode": "801081", "name": "半导体", "level": 2, "parentCode": "801080",
          "l1Name": "电子", "memberCount": 180, "directMemberCount": 7,
          "children": [
            { "swCode": "850812", "name": "分立器件", "level": 3, "parentCode": "801081", "l1Name": "电子", "memberCount": 18, "directMemberCount": 18, "children": [] }
          ]
        }
      ]
    }
  ] }
```

> **字段名（v1.3 起统一 camelCase）**：`swCode` / `parentCode` / `l1Name`；原始列名别名
> `sw_code` / `parent_code` / `l1_name` **已移除**（前端原有 `n.swCode || n.sw_code` 兜底不受影响）。
> **`memberCount` 语义**：该行业在 `t_industry_member` 里的当前成分股数。
> ⚠️ **一级行业的 `memberCount` 恒为 `0`** —— 成分股只挂在二/三级（实测 `t_industry_member`
> 只有 L2 8,170 行 / L3 7,599 行，L1 零行）。不要把它当成「一级行业成分股总数」，
> 需要一级口径请用其二级子行业求和。
> `directMemberCount` 含义同 §3.3；前端判定二级行业是否需要渲染「未细分到三级」分组时用它，**无需额外请求**。

### 3.5 行业详情

`GET /api/v1/industries/801081`

```json
{ "code": 0, "msg": "ok",
  "data": {
    "swCode": "801081", "name": "半导体", "level": 2,
    "l1Code": "801080", "l1Name": "电子",
    "memberCount": 180,
    "summary": {
      "todayNet": -132.3201, "net5d": -356.2042, "net10d": -198.6068,
      "todayMain": -97.6903, "main5d": -373.117, "main10d": -152.2493,
      "turnover": 1774.5337
    }
  } }
```

> `summary` 的 `net5d/net10d/main5d/main10d` 与 §3.3 列表**同口径**（最近 5/10 个交易日累计）；
> `todayNet/todayMain/turnover` 取该行业自身最新一行。
> `main5d/main10d` 是 v1.3 新增，原文档称「列表有、详情无」的不对齐已消除。
> 不存在时返回 `40401`。

### 3.6 行业成分股

`GET /api/v1/industries/801081/members?as_of=2026-09-24&page=1&page_size=50`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| as_of | string | 否 | 历史时点；**缺省 = 当前成分**（`out_date IS NULL`） |
| direct | int | 否 | `1` = 只返回**直属成分股**（未被任一下级子行业覆盖）；默认 `0` |
| page / page_size | int | 否 | 分页（≤100） |

```json
{ "code": 0, "msg": "ok",
  "data": {
    "asOf": "2026-09-24",
    "list": [ { "tsCode": "001309.SZ", "name": "德明利", "inDate": "2024-07-31", "outDate": null } ],
    "total": 180, "page": 1, "page_size": 50
  } }
```

> 传入 `as_of` 时按 `in_date <= as_of AND (out_date IS NULL OR out_date > as_of)` 取时点成分；不传则返回当前成分，且 `asOf` 为 `null`。
> **`asOf` 回显统一 `YYYY-MM-DD`**：`?as_of=20260924` 与 `?as_of=2026-09-24` 都回显 `"2026-09-24"`（v1.3 前是原样回显 `20260924`，与同一响应里的 `inDate` 格式冲突）。
> **行业不存在时返回 `40401`**（v1.3 前返回 `code:0` + 空列表，前端无法区分「行业不存在」与「行业存在但暂无成分股」）。
> 非法日期（`?as_of=abc`、`20261301`）返回 `40001`，不落库查询。
>
> **`direct=1`** 用于取二级行业的「未细分到三级」股票。例：`/industries/801156/members?direct=1` 返回 7 只（`000504.SZ` 南华生物等），而默认返回全部 51 只——差的这 44 只已归入其三级子行业，`direct=1` 可避免前端拿到全量后自行做集合差（否则需 `1 + N` 次请求）。三级行业无子节点，`direct=1` 与默认结果一致；`direct` 与 `as_of` 可同时使用，时点谓词对两侧一致生效。

### 3.7 行业资金流

`GET /api/v1/industries/801081/flow?start=2026-09-01&end=2026-09-24`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| start / end | string | 否 | 日期区间；**缺省返回全部已有数据**（非"近 60 日"） |

```json
{ "code": 0, "msg": "ok",
  "data": {
    "swCode": "801081", "name": "半导体", "level": 2,
    "series": [
      { "d": "2026-09-24",
        "sm": 57.6218, "md": 34.8895, "lg": -20.7296, "elg": -71.7817,
        "main": -92.5113, "net": -136.1224,
        "turnover": 2057.4007, "memberCount": 180 }
    ]
  } }
```

字段：`sm/md/lg/elg` = 小/中/大/超大单净额（亿元）；`main = lg + elg`；`net` = 官方净流入；`turnover` = 成交额；累计值由前端计算（表内无 `cum_*` 列）。

> ⚠️ **更正（v1.3）**：本文档曾写「**仅二级行业有数据**」，**实测相反** —— `t_industry_flow`
> 的 L1/L2/L3 三级都有数据（7,533 / 30,132 / 62,694 行；31 个一级行业每个都有完整 243 天）。
> 这句话曾导致前端对用户显示「该层级资金流暂未聚合」，属于「库里有数据却告诉用户没有」。
> **真正存在的是三级行业的「源端稀疏」**：346 个三级行业里有 72 个在数据源端就没有成分股，
> 因而永远算不出资金流 —— 前端对这类节点应显示「暂无成分股」空态，而不是把它当成后端不支持三级。
> 不存在时返回 `40401`；`start > end` 返回 `40001`。

### 3.8 个股资金流

`GET /api/v1/stocks/600519.SH/flow?start=2026-09-22&end=2026-09-24`

{ "code": 0, "msg": "ok",

    "industry": "白酒Ⅱ", "industryCode": "801125",

### 3.9 股票搜索

`GET /api/v1/stocks/search?q=茅台&page=1&page_size=10`

```json
{ "code": 0, "msg": "ok",
  "data": {
    "list": [ { "tsCode": "600519.SH", "name": "贵州茅台", "industry": "白酒Ⅱ", "industryCode": "801125",
                "l3Code": "851251", "l3Name": "白酒Ⅲ", "hasL3": true } ],
    "total": 1, "page": 1, "page_size": 10
  } }
```

> `industry` 优先取当前所属二级行业名，取不到才回退 `t_stock_basic.industry`。
> **`q` 为必填参数（`required: true`，至少 1 字符）**：不带 `q` 或 `q=` 一律返回 **HTTP 422**。
> （v1.3 只是把 OpenAPI 里的契约写对——原先写作 `Query("", min_length=1)`，OpenAPI 显示「可选、默认空串」；
> 另有审查结论推断「不带 q 会返回全部 5,571 只」，**实测不成立**，FastAPI 对默认值同样做 `min_length` 校验。）
> **`total` 是命中总数，不受 `page_size` 截断**：前端应用它提示「共 N 条，显示前 100」，不要当成只有这么多。
>
> **`l3Code` / `l3Name` / `hasL3`**：该股当前所属三级行业。`hasL3=false`（`l3Code=null`）表示**没有三级归属**——数源 `index_member` 未提供，不是同步丢失。前端应把这类命中结果渲染到其二级行业（`industryCode`）下的「未细分到三级」分组，否则它们在任何三级节点里都找不到位置，表现为"搜索不到"。
> 实例：`q=000504` → `{"tsCode":"000504.SZ","name":"南华生物","industry":"医疗服务","industryCode":"801156","l3Code":null,"hasL3":false}`。

### 3.10 行业成分股区间资金流排行

`GET /api/v1/industries/801081/stocks-flow?start=2026-07-31&end=2026-09-24&limit=40`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| start / end | string | 否 | 区间；缺省为全部已有数据 |
| limit | int | 否 | 返回条数，默认 100，上限 500 |

```json
{ "code": 0, "msg": "ok",
  "data": {
    "swCode": "801081",
    "list": [
      { "tsCode": "688012.SH", "name": "中微公司", "net": 46.0633, "main": 30.12, "turnover": 210.55 }
    ]
  } }
```

> 按区间 `net` 降序；成分按**时点成分**关联（`in_date <= trade_date < out_date/∞`）。
> ⚠️ **更正（v1.3）**：本文档曾写「当前仅二级行业有成分数据」，**实测相反** ——
> `t_industry_member` 的 L2/L3 都有成分（当前活跃 5,191 / 4,938 只），**只有 L1 没有成分行**。
> 不存在时返回 `40401`。`net/main/turnover` 是**区间累计**值，与 §3.3 的 `todayNet`（当日值）同名不同义。

### 3.11 全市场二级行业强度

`GET /api/v1/strength`（无参数）

```json
{ "code": 0, "msg": "ok",
  "data": {
    "list": [
      { "swCode": "801012", "name": "农产品加工", "l1Name": "农林牧渔",
        "net": -12.34, "turnover": 380.5, "strength": -0.032116 }
    ]
  } }
```

> `strength = net / turnover`（区间净流入 ÷ 区间成交额），基于**全部已有数据**计算（非按天窗口）；`turnover=0` 时为 `null`。仅返回有聚合数据的二级行业。

### 3.12 触发采集（管理）

`POST /api/v1/admin/fetch`
请求头：`X-Admin-Key: <key>`（必填）　|　请求体：

```json
{ "task": "all" }
```

```json
{ "code": 0, "msg": "ok", "data": { "task": "all", "status": "accepted" } }
```

> 实现说明：`task` 取自 **JSON 请求体**，取值 `all`（默认）｜`meta`｜`members`｜`moneyflow`｜`aggregate`｜**`incremental`**
> （`incremental` 是最省配额、日常在用的那个：只补缺失日期 + 空洞自愈，无新数据时不触发任何采集与聚合）；
> 在后台线程执行 `etl.main([task])`；未知取值返回 `40001`；并发触发返回 `42901`；鉴权不通过返回 `40102`。
> 响应无 `startedAt`。**真实进度请用 `GET /admin/log`**。
>
> **并发护栏（v1.3 修复）**：进程内 `FetchGate`（请求线程原子占用、worker 结束才释放）
> + `t_fetch_log` 中未结束的 `running` 行（跨进程兜底；超过 `FETCH_STALE_MINUTES`（默认 360）的
> 孤儿行会被忽略）。修复前锁在启动线程后立刻释放，两次并发 POST 会同时跑两个 ETL
> 并互相截断同一份 `etl_run.log`，`42901` 实际不可达。
> **真实采集进度与结果**见 `t_fetch_log`（每次运行一行：`running` → `success`/`partial`/`failed`，
> 含 `rows_fetched` / `rows_written` / `error_msg`）。

### 3.13 采集日志（管理）

`GET /api/v1/admin/log?lines=200`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| lines | int | 否 | 返回尾部行数，默认 200，上限 2000 |
| offset | int | 否 | 从第几行开始取（**1-based**）；给了 `offset` 就返回该窗口而非尾部 |

请求头：`X-Admin-Key: <key>`（必填）

```json
{ "code": 0, "msg": "ok",
  "data": {
    "exists": true,
    "total": 73,
    "mtime": "2026-09-29 23:35:52",
    "lines": ["[23:32:44] P0 ETL 启动 task=members …", "…", "[23:35:52] P0 ETL 完成（task=members）"]
  } }
```

> 读取后端 `cfg.log_file`（默认 `backend/etl_run.log`）尾部；**单次遍历同时完成计数与取样**。
> 管理页可据此展示**真实采集进度**
> （例如匹配末尾的「P0 ETL 完成」判定结束，或从 `P0 ETL 启动` 判定开始）。
> 注意：`etl.py` 每次启动会**清空重写**该日志，因此进度是「本次运行」的。
> **增量拉取**：传 `offset=<上一轮 total+1>` 可只取新增行，从而避免管理台在尾部 200 行饱和后
> 「看起来卡住」（前端配合改造，见审查报告 6.1 P2）。

## 7. 静态前端托管

FastAPI 通过 `StaticFiles` 挂载 `backend/static/` 到 `/`，可直接访问：

- `http://127.0.0.1:8000/` → **307 重定向到 `/industry.html`**（看板入口）

> `backend/static/` 是**唯一开发源**（根目录同名文件是 GitHub Pages 发布副本）。
> ⚠️ **同步方向已裁决**：早期文档 `docs/04-前端改动说明-未细分到三级.md` 曾声称
> 「根目录是源文件、`static/` 是副本，需按 §7 同步」——**该文档已删除**，因为它的结论是错的：
> 「未细分到三级」功能**只存在于 `backend/static/` 版**（根版 0 处命中），
> 照它做「根 → static 同步」会**静默回退已上线功能**（见审查报告 S4）。
> 改动一律改 `backend/static/` 下的文件。
> ⚠️ 静态文件目前**没有** `ETag` / `Cache-Control`，浏览器可能缓存旧页面，调试时请强制刷新。
