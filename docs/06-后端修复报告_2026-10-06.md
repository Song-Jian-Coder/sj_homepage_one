## 2. P0 修复（5 条，全部已修）

### 2.1 `5.1.1 /health` 降级分支不可达 → 已修

`app/routers/health.py`。**不再用 `Depends(get_conn)`**：依赖注入会在进入函数体前 `connect()`，
失败即 500，`except` 分支永远不可达；现在把「取连接 + 两条查询」全部纳入同一 `try`，

证据（真实 HTTP，uvicorn :8123）：

```

```

### 2.2 `5.1.2 /admin/fetch` 并发护栏是空操作 → 已修

`app/services/admin.py:FetchGate` + `app/routers/admin.py`。改为**请求线程原子占用

## 4. 对审查报告的 3 处改判 / 补充

沿用你在 §3 里"先讲我改判了什么"的做法，我也把自己的复核结论单列，避免夸大。

### 4.1 ⚠️ `5.7.2` 的**影响面**不成立：不带 `q` 实测返回 422，不是「返回全部 5,571 只」

报告称 `Query("", min_length=1)` 的 OpenAPI 显示"可选、默认空串"，因此
「不带 `q` 请求 `/stocks/search` 会执行 `LIKE '%%'` 返回全部 5,571 只」。

**实测不成立**：FastAPI 对默认值同样执行 `min_length` 校验。改造前的契约快照里，
`GET /api/v1/stocks/search`（无参数）与 `?q=` **都是 HTTP 422**
（`detail[0].type = string_too_short`）。

**正确定性**：只是**契约表述**错误（OpenAPI 里 `q` 显示为非必填、默认 `''`，与 `docs/03` 的
"必填"不符），不是安全/正确性缺陷。**已修**：改为 `Query(..., min_length=1)`，
OpenAPI 现在如实标注 `required: true`；运行期行为与改造前一致（仍 422，仅 `detail[0].type`
由 `string_too_short` 变为 `missing`）。`docs/03 §3.9` 已把这条实测结论写进文档。

### 4.2 `6.7` 表格把 `/industries/{c}`（详情）列为 `industry.html` 的调用 → 实为 `/members`

`industry.html:544,571` 调用的是 `/api/v1/industries/{code}**/members**`。
**详情端点（`GET /industries/{sw_code}`）当前没有任何前端调用者**（全 7 个页面均未调用）。
这直接影响你的 5.7.9 判断的风险等级：给详情 `summary` 补 `main5d/main10d`、
以及把 `net5d/net10d` 改成与列表同口径，**是零回归风险的**（无人消费）。
（我仍按你的建议补齐并对齐了，同时保留 `todayNet/todayMain/turnover` 的原有语义。）

## 7. 风险与回滚

**风险**

1. **连接池**：池化后连接被复用，若某处忘记 `rollback`/`commit`，脏事务可能回流。
   缓解：`Pool.release()` 无条件 `rollback`；API 侧全部为只读查询（唯一写操作是管理接口的审计行）。
2. **60s TTL 缓存**：数据更新后最长 60s 陈旧。缓解：`API_CACHE_TTL=0` 可完全关闭；
   采集/管理页看到的 `t_fetch_log`、`/admin/log`、`/health` **不走缓存**。
3. **`/tree` 删键**：虽然已确认前端有兜底，但仓库外若有未在此清单里的消费者，会受影响。
   若要绝对稳妥，可把 `TreeNode` 加回一个 `sw_code` 兼容字段（一行代码）。
4. **DDL 未变更**：本轮**没有改任何表结构**（`schema.sql` 只加了注释），因此**不需要迁移**，
   `stock_data` 现状与代码一致。（无迁移工具仍是既有债务，见 §8。）
5. **未跑真实采集**：ETL 行为由 21 项自检 + 单测覆盖，但「真实 HTTP 拉 242 天」这条链路
   本轮未实际执行（不消耗配额）。第一次真实运行建议在低峰期执行
   `python etl.py incremental`，观察 `etl_run.log` 与 `t_fetch_log`。
