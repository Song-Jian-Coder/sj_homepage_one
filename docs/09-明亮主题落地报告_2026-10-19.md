# 09 明亮主题落地报告（B 方案：明亮为默认 + `?theme=dark` 开关）

- 日期：2026-10-19
- 范围：`backend/static/common.js`、`fundflow.html`、`industry.html`、`admin.html`
- 未改动：根目录同名 HTML（GitHub Pages 发布副本）、`index.html`（个人主页，不属于看板体系）
- 结论：**明亮主题已生效为默认；暗色保留且可切换；24 项浏览器回归全过，7 个 XSS 载荷全过，无运行期异常。**

## 1. 做了什么

### 1.1 主题机制（`common.js` 新增第 7 节）

| 函数 | 作用 |
|---|---|
| `themeGet()` | 取当前主题：`?theme=` > `localStorage['sw-theme']` > 默认 `light` |
| `themeSet(name)` | 写 `<html data-theme>`，同步 `color-scheme`，持久化到 localStorage |
| `themeToggle()` | 明亮 ↔ 暗色 |
| `onThemeChange(fn)` | 注册监听（切主题后需要重绘的页面用） |

按项目既有约定，**四个函数同时挂到 `global` 和 `SW.*`**——只挂 `SW.X` 会在普通 `<script>` 里运行期报 `X is not defined`（`check-globals.js` 已验证无缺失）。

### 1.2 防闪烁（FOUC）

三个页面在 **CSS 之前**各注入一段内联脚本设置 `data-theme`。不能调用 `common.js` 的 `themeGet()`，因为外部脚本执行时机在首屏之后，暗色用户会先看到一帧白屏。

规则与 `themeGet()` 一致，`localStorage` 访问包在 `try/catch` 里（隐私模式 / `file://` 下会抛异常）。

### 1.3 CSS 变量收敛

明亮值写在 `:root`，暗色只在 `html[data-theme="dark"]` 下覆盖。

新增变量用于收口原先散落的「暗色专用 rgba」。原方案列的 ~15 处是**低估**，实际按页统计见 §3。

### 1.4 JS 侧色阶

`fundflow.html` 的 `UP_STEPS` / `DN_STEPS` 改为 `TILE_STEPS = { light: {...}, dark: {...} }`，`tileColor()` 按 `themeGet()` 取值。平盘兜底色由 `'#22252a'` 改为 `var(--surface-2)`。

`industry.html` 的趋势图 `stroke="#8b93e8"` → `var(--chart-line)`，面积 `fill` → `var(--chart-area)`，四档配色 `QCOLOR` 本来就走 `var(--q-*)`，只需换变量值。

## 2. 对比度：原方案里的估算被实测推翻

**这是本次改动最重要的一节。** 我先按 WCAG 公式实测，结果发现原方案（以及我给的第一版实现）里有两处**不达标**：

### 2.1 热力图色阶：第 5 档无论深字白字都不够

第一版按 `10/18/28/44/64/88` 排透明度，深字 `#a3242a`、后四档白字。实测（对纯白底合成后）：

| 透明度 | 合成底色 | 深字对比 | 白字对比 | 判定 |
|---|---|---|---|---|
| 10% | (250,235,235) | 8.99 | 1.16 | 深字 ✓ |
| 18% | (247,218,219) | 7.96 | 1.31 | 深字 ✓ |
| 28% | (242,198,199) | 6.79 | 1.53 | 深字 ✓ |
| 44% | (235,166,167) | 5.21 | 2.00 | 深字 ✓ |
| **64%** | (226,125,128) | **3.70** | **2.81** | **都不达标** |
| 88% | (215,76,80) | 2.50 | 4.17 | 白字勉强 ✓ |

第 5 档深字 3.70、白字 2.81，**两边都过不了 4.5**。靠"前两档深字、后四档白字"的分法根本走不通。

**修法**：透明度阶梯改为 `10/20/32/50/80/100`，跳开不可达的中间地带；主色加深到 `#b8202a`（红）/ `#086246`（绿），文字色深字用 `#6b171c` / `#043626`。实测全部达标：

| 透明度 | 红 | 绿 |
|---|---|---|
| 10% | 深字 10.08 | 深字 11.52 |
| 20% | 深字 8.47 | 深字 9.77 |
| 32% | 深字 6.79 | 深字 7.91 |
| 50% | 深字 4.77 | 深字 5.60 |
| 80% | 白字 4.58 | 白字 4.62 |
| 100% | 白字 6.41 | 白字 7.38 |

### 2.2 状态色/辅助文字未达 AA

| 变量 | 原方案值 | 实测 | 修正为 | 实测 |
|---|---|---|---|---|
| `--text-dim` | `#6b7684` | 3.90 ✗ | `#66717e` | 4.84 ✓ |
| `--down` / `--ok` | `#0f8a63` | 4.23 ✗ | `#0b7d59` | 5.00 ✓ |
| `--warn` | `#b26a00` | 4.13 ✗ | `#9a5c00` | 5.24 ✓ |

> 我在上一轮方案里写的是"`--text-dim` 3.9（仅用于 ≤12px 辅助信息）"—— 这是在**给不达标找理由**。本次一并修正到 4.84。

## 5. 主动偏离 / 未能验证 / 自己引入的问题

### 5.1 主动偏离原方案

1. **色阶透明度阶梯改了**：原方案 `10/18/28/44/64/88` 以 `#d13438` 为基准；实测第 5 档不可达，改为 `10/20/32/50/80/100` + 加深主色（§2.1）。
2. **`--text-dim` 从 `#6b7684` 改为 `#66717e`**：原方案说"3.9 可用于辅助信息"，属于为不达标找理由，本次修正到 4.84。
3. **`--down`/`--ok` 从 `#0f8a63` 改为 `#0b7d59`，`--warn` 从 `#b26a00` 改为 `#9a5c00`**：原值 4.13–4.23 未达 AA。
4. **admin 的 `.btn-accent` 文字色改为变量**：原方案没提，但明亮下 `--ok` 变深后必须保留白字、暗色下必须保留深字，否则会白字白底。

### 5.2 自己引入并已修复的问题

| 问题 | 发现方式 | 修法 |
|---|---|---|
| `industry.html` 顶栏明亮下变黑条 | 截图 | `rgba(10,11,13,.88)` → `var(--chrome)` |
| 热力色阶第 5 档两侧都不达标 | Python 逐档算对比度 | 重排阶梯 + 加深主色 |
| `--text-dim`/`--down`/`--warn` 未达 AA | 同上 | 见 §2.2 |

### 5.3 未能验证 / 已知遗留

1. **admin 的「全量更新」按钮在明亮下偏灰**：查证后是**禁用态**（未填 `ADMIN_KEY` 时 `disabled`），不是配色缺陷。填入密钥后的启用态未截图验证（需要真实执行 ETL，本次刻意未触发）。
2. **暗色主题的多处半透明色未逐档实测**：暗色沿用原有值（本次只是把它搬进 `[data-theme="dark"]`），未做对比度复核。原有暗色本身可能存在个别不达标处，属历史问题，未纳入本次范围。
3. **`--chrome` 在 `fundflow` 与 `industry` 里取值不同**：`fundflow` 用 `.86`、`industry` 用 `.88`。这是照抄原值，未统一——若要统一需另做视觉确认。
4. **未做首屏 FOUC 的帧级验证**：防闪烁脚本已就位且 `data-theme` 在 CSS 前设定，但未用录屏/`Performance` 抓首帧证明"暗色用户不会闪白"。
5. **根目录发布副本未同步**：按项目约定**不要**做「根 → static 同步」。但需注意 GitHub Pages 上的副本仍是旧样式，若要视觉一致需另行处理。

## 6. 回滚方式

单点回滚：删掉三个页面 `<head>` 里那段防闪烁内联脚本 + `<button class="theme-sw">` 及其绑定 + 删掉 `html[data-theme="dark"]` 块，把 `:root` 的值换回原暗色值即可。`common.js` 的主题模块是**纯新增**，不删也不影响原逻辑。

建议用 `git diff` 逐页核对，`:root` 与 `[data-theme="dark"]` 两块互不重叠，便于局部取舍。
